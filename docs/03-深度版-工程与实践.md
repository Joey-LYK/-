## 第一章 优化算法进阶

> 核心问题：nn.c 目前用的是最简单的 SGD（随机梯度下降），每步只用当前一个样本的梯度更新权重。这够用吗？

### E-01 SGD 的缺陷

项目当前的训练方式就是纯 SGD——每个样本算一次梯度，更新一次权重。

**问题 1：震荡**

```
假设损失函数的地形像一个狭长的山谷：
  SGD 会沿着山坡"左右摇摆"着前进，而不是沿着谷底直线走
```

**问题 2：对不同参数用相同的学习率**

```
有些权重需要大幅度调整，有些只需要微调
SGD 统一用 lr，无法区分
```

**问题 3：学习率选择困难**

```
lr 太小 → 收敛极慢
lr 太大 → 震荡甚至发散
没有"自适应"机制
```

### E-02 动量法

**比喻：小球滚下山**

想象一个球从山坡上滚下：
- 如果每步只看当前坡度，球容易被困在局部小坑里（局部最优）
- 如果球有"惯性"（动量），它能冲过小坑继续向更低处滚动

**数学表达**：

```
v[t] = β × v[t-1] + (1-β) × gradient    ← 速度 = 惯性 + 新梯度
θ[t] = θ[t-1] - lr × v[t]               ← 位置按速度更新
```

其中 β（动量系数，通常 0.9）控制惯性大小。

**效果**：
- 方向一致的梯度会被"加速"（累积速度）
- 方向交替的梯度会被"抵消"（惯性缓冲震荡）

**与 nn.c 的关系**：当前 nn.c 的 `nn_update` 中没有动量机制，每步更新都是独立的。如果加入动量，需要为每个权重维护一个速度变量。

### E-03 Adam 算法

Adam 是当前深度学习的事实标准，结合了动量和自适应学习率。

**核心思想**：

```
对每个参数：
1. 维护一个"速度"（一阶矩估计 m）——类似动量
2. 维护一个"速度的平方"（二阶矩估计 v）——用于自适应学习率
3. 用偏差修正消除初始化偏差
4. 用自适应学习率更新参数
```

**更新规则**：

```
m = β₁ × m + (1-β₁) × gradient      ← 一阶矩（速度）
v = β₂ × v + (1-β₂) × gradient²    ← 二阶矩（速度平方）

m̂ = m / (1 - β₁^t)                       ← 偏差修正
v̂ = v / (1 - β₂^t)                       ← 偏差修正

θ = θ - lr × m̂ / (√v̂ + ε)          ← 参数更新
```

**默认参数**：β₁=0.9, β₂=0.999, ε=1e-8

**为什么 Adam 好？**

| 特性 | 纯 SGD | 动量法 | Adam |
|------|--------|--------|------|
| 方向自适应 | ❌ | ✅ | ✅ |
| 步长自适应 | ❌ | ❌ | ✅ |
| 初始化敏感 | 高 | 中 | 低 |
| 计算开销 | 最低 | 低 | 中 |

### E-04 学习率调度

**为什么后期要降低学习率？**

> 训练初期，损失地形陡峭，需要大步快走
> 训练后期，接近最优解，地形平缓，需要小步精调
>
> 如果一直用大学习率，会在最优解附近来回震荡，永远无法精确收敛

**常见调度策略**：

| 策略 | 公式 | 特点 |
|------|------|------|
| 指数衰减 | lr = lr₀ × decay^step | 平滑衰减 |
| 阶梯衰减 | 每 N 步 lr 减半 | 简单粗暴 |
| 余弦退火 | 先线性升温再余弦下降 | 热门方法 |
| 预热重启 | 训练中途重置学习率 | 跳出局部最优 |

### E-05 优化算法选型指南

| 场景 | 推荐算法 | 原因 |
|------|---------|------|
| 资源极度受限（MCU） | 纯 SGD | 不需要额外内存 |
| 一般嵌入式 | SGD + 动量 | 仅多一组速度变量 |
| 需要快速收敛 | Adam | 自适应学习率省去调参 |
| 精度要求极高 | Adam + 衰减 | 后期小步精调 |
| 训练数据量大 | Adam + 大 batch | 梯度估计更准确 |

## 第二章 泛化能力与过拟合

### E-06 过拟合与欠拟合

**三种状态的诊断表**：

| 状态 | 训练 Loss | 验证 Loss | 玟因 | 解决方案 |
|------|----------|----------|------|---------|
| 欠拟合 | 高 | 高 | 模型太简单，学不到 | 增加层/神经元 |
| 正常 | 低 | 低 | 模型合适 | 保持 |
| 过拟合 | 低 | 高 | 模型太复杂，背答案 | 减小模型/正则化 |

**如何判断？**

在当前项目中，`train_demo.c` 的验证阶段（第 96~125 行）就是"验证"——用训练没见过的样本测试。

> **检查点**：你的 sin(x) 任务训练完后，给一个训练范围内没出现过的 x 值（比如 π+0.01），预测准确吗？

### E-07 训练集 / 验证集 / 测试集

| 数据集 | 用途 | 类比 |
|--------|------|------|
| 训练集 | 训练用 | 做练习册 |
| 验证集 | 调参用 | 模拟考（决定何时停止训练、选哪个超参数） |
| 测试集 | 最终评估 | 正式考试（训练和调参时都不能碰） |

**当前项目的数据情况**：

项目用的是**在线生成**的方式（`task_*.c` 中的 `generate()` 函数），没有显式的数据集划分。

- sin(x)：随机生成，每次都是新样本 → 天然具备"验证集"效果
- XOR：数据量极小（只有 4 种输入组合），容易过拟合

### E-08 L2 正则化

**核心思想：惩罚大权重。**

```
L_正则化 = L_原始 + λ × Σ(w²)
```

效果：
- 权重更小 → 模型更"平滑"，不会对单个特征过度依赖
- 模型更简单 → 泛化能力更强（类似"奥卡姆剃刀"——去掉不必要的复杂度）

**与 nn.c 的关系**：当前 nn.c 没有实现 L2 正则化。如果需要，在 `nn_update` 中加一行：

```c
// 伪代码：L2 正则化
cur->weights[...] -= lr * gradient;
cur->weights[...] -= lr * lambda * cur->weights[...];  // 额外衰减
```

### E-09 Dropout

**核心思想：训练时随机"关闭"部分神经元，防止网络过度依赖特定路径。**

```
训练时：
  输入 → [神经元1] [神经元2 ✗] [神经元3] → 输出  ← 神经元2 被关闭
  
测试时：
  输入 → [神经元1] [神经元2] [神经元3] → 输出  ← 全部开启，但每个神经元输出乘 (1-dropout_rate)
```

效果：
- 迫使网络不能依赖任何单个神经元 → 被迫学习更鲁棒的特征
- 相当于训练了多个子网络的"集成" → 提高泛化

**当前项目适用性**：Dropout 需要改前向传播和反向传播，对 nn.c 的改动较大，适合作为独立练习。

### E-10 早停法

**核心思想：监控验证集 Loss，当验证集 Loss 不再下降时停止训练。**

```
epoch:  1   2   3   ...  50  51  52  53  54
训练:  ↓   ↓   ↓       ↓   ↓   ↓   ↓   ↓
验证:  ↓   ↓   ↓       ↓   ↑   ↑   ↑   ← 从这里开始验证 Loss 上升了！
                              ↑
                           在这里停止训练
```

**当前项目中**，`train_demo.c` 用固定的 epochs 训练，没有早停机制。如果加入早停，需要在训练循环中增加验证步骤。

## 第三章 数据工程

### E-11 数据采集策略

**没有仿真时，真实数据怎么来？**

| 策略 | 描述 | 适用场景 |
|------|------|---------|
| 离线采集 | 先收集一批数据存文件，再用文件训练 | 能控制实验条件（如实验室） |
| 在线学习 | 系统运行时实时收集数据，实时训练 | 系统能长期运行且允许试错 |
| 仿真预训练 | 先用物理模型生成大量数据训练，真实数据微调 | 有足够准确的物理模型 |

**数据量需要多少？**

经验法则（不是精确公式）：

```
参数量 × 10 ~ 参数量 × 100 条样本
```

你的项目中最小的 XOR 任务有 5 个参数（1×4+1），理论上 50~500 条就够。

### E-12 数据归一化

**为什么需要归一化？**

> 归一化就是把输入数据压缩到 [0, 1] 或 [-1, 1] 的范围内。

如果不归一化：
- 输入值很大（比如 vx=200），乘以权重后加权和极大
- 激活函数（Sigmoid/ReLU）饱和 → 梯度消失
- 学习率对不同尺度的输入效果不一致

**对应项目代码**：`task_projectile.c` 第 60~62 行：

```c
// task_projectile.c 第 60~62 行
input[0]  = vx / 200.0;      // vx ∈ [0.25, 1.0]
input[1]  = vy / 200.0;      // vy ∈ [0.25, 1.0]
target[0] = x  / 1000.0;     // 落地距离 ∈ ~[0, ~2.0]
```

速度 50~200 除以 200 → [0.25, 1.0]，距离除以 1000 → [0, ~2.0]。

> **检查点**：如果速度范围改成 500~800，除以多少合适？为什么？

### E-13 数据增强

**核心思想：用有限的原始数据，通过变换创造更多的训练样本。**

| 变换方式 | 例子 |
|---------|------|
| 加随机噪声 | 温度值 ± 0.5°C |
| 随机缩放 | 电压值 × (0.95~1.05) |
| 时间窗口平移 | 传感器数据起始时间随机偏移几秒 |
| 特征组合 | 两个传感器数据打乱顺序 |

**当前项目**：sin(x) 任务天然具备数据增强效果——每次 `rand()` 生成的 x 值都不同，相当于无限多的样本。

### E-14 在线学习 vs 离线学习

| 对比 | 离线学习 | 在线学习 |
|------|---------|---------|
| 数据 | 先收集完再训练 | 实时收集实时训练 |
| 优点 | 训练稳定 | 不需要预采集数据 |
| 缺点 | 需要存储大量数据 | 早期预测质量差 |
| 适用 | 能控制实验条件 | 系统持续运行，允许试错 |

**当前项目两种模式都有**：

- `train_demo.c` = 离线训练（虽然数据是实时生成的，但每轮独立，不依赖过去经验）
- `main.c` = 在线学习（每帧训练 1000 步，利用已训练的模型继续改进）

### E-15 仿真预训练 + 真实微调

**这正是你的项目在做的事情。**

```
Step 1: 仿真生成大量数据 → 训练出基础模型
  （train_demo.exe 或 main.c 的训练阶段）
  
Step 2: 保存模型到文件 → nn_export
  （main.c 的 PX_AnnSaveToFile）
  
Step 3: 加载已训练模型 → 用真实数据微调
  （main.c 的 PX_AnnLoadFromFile）
```

**为什么这个策略有效？**

> 仿真模型捕获了"大致规律"（比如抛体运动的物理趋势），
> 真实数据修正"仿真和现实的偏差"（比如空气阻力、摩擦力）。
>
> 相比从零开始用真实数据训练，需要的真实数据量大为减少。

## 第四章 模型序列化与部署

### E-16 模型导出格式设计

**nn_export 的二进制格式**（nn.c 第 460~515 行）：

```
┌──────────────────────────────────┐
│ magic: "NN01"          4 bytes │ ← 版本标识
│ layer_count: int          4 bytes │ ← 层数
│ learning_rate: double     8 bytes │ ← 学习率
├──────────────────────────────────┤
│ per layer:                         │
│   size:       int         4 bytes │
│   activation: int         4 bytes │
│   input_size: int        4 bytes │
│   (若 input_size > 0):             │
│     weights: double[]           │
│     biases:  double[]           │
└──────────────────────────────────┘
```

**设计要点**：

1. **magic 校验**：读取前 4 字节，不是 "NN01" 就拒绝加载 → 防止误加载
2. **版本兼容**：以后如果增加字段，可以通过 magic 区分不同版本
3. **紧凑存储**：只存储可训练参数（weights + biases），不存储运行时缓存

### E-17 模型导入与验证

`nn_import`（nn.c 第 517~575 行）的验证步骤：

```
Step 1: 校验 magic 是 "NN01"
Step 2: 读取 layer_count、learning_rate
Step 3: 逐层读取 size、activation、input_size
Step 4: 如果有 input_size > 0，读取 weights 和 biases
Step 5: 用 nn_add_layer 重建网络结构，用导入值覆盖随机初始化的权重
```

**安全性检查**：
- 文件大小检查：`if (size < 16) return NULL` → 防止截断文件
- 内存分配检查：`malloc` 返回 NULL → 处理内存不足

### E-18 版本兼容性

**如何兼容旧模型？**

如果未来要在格式中增加字段（比如增加 batch norm 参数）：

```
方案 1: 升级 magic（推荐）
  旧 magic: "NN01"
  新 magic: "NN02"
  → nn_import 读取 magic 时判断版本，用不同的解析逻辑

方案 2: 在末尾追加字段
  保持旧格式不变，在尾部追加新的可选字段
  → 旧版本加载时忽略末尾多余字节
```

### E-19 文件 I/O 与 Flash 存储

**在嵌入式平台上持久化模型**：

| 存储介质 | 容量 | 特点 |
|---------|------|------|
| SD 卡 / eMMC | 大 | 读写方便，支持文件系统 |
| NOR Flash | 中 | 需要手动管理地址，写入速度慢 |
| 内部 Flash (STM) | 小 | 直接映射到地址空间，读取极快 |

**对应 main.c 的实现**（`PX_AnnSaveToFile` / `PX_AnnLoadFromFile`）：

```c
// 使用 PainterEngine 的文件 I/O
nn_export(ann, PX_NULL, &size);        // 获取大小
buffer = MP_Malloc(mp, size);
nn_export(ann, buffer, &size);          // 导出到内存
PX_SaveDataToFile(buffer, size, filename);  // 写入文件
```

**Flash 磨写注意**：NOR Flash 擦写前需要先擦除整个扇区（通常 4KB 为一个扇区），频繁写入会降低寿命。

## 第五章 嵌入式部署优化

### E-20 参数量与内存估算

**参数量计算公式**：

```
总参数 = Σ(每层参数)
每层参数 = output_size × input_size + output_size
         = output_size × (input_size + 1)        ← 权重 + 偏置
```

**你的项目实例**：

| 任务 | 结构 | 参数量 | 内存（float64） |
|------|------|--------|--------------|
| sin(x) | 1→16→16→1 | 49 | 392 bytes |
| XOR | 2→4→1 | 13 | 104 bytes |
| 抛体 | 2→64→128→1 | 8,577 | 68,616 bytes (~67 KB) |

**嵌入式内存占用估算**：

```
运行时内存 ≈ 参数量 × 8 bytes (float64)
         + 每层缓存的 net[] 和 out[] 
         + 每层缓存的 error[]
```

对于 STM32F407（192KB RAM）：
- sin(x) 模型完全可以放下
- 抛体模型占 RAM 约 70KB，需要规划是否与其他模块共享

### E-21 推理延迟估算

**一次前向传播的计算量**：

```
FLOPs ≈ Σ(每层计算量)
每层计算量 = output_size × input_size × 2   (一次乘法 + 一次加法)
```

**sin(x) 模型**：16×1 + 16×16 + 1×16 = 49+256+16 = 321 FLOPs

**抛体模型**：64×2 + 128×64 + 1×128 = 128+8192+128 = 8,448 FLOPs

在 STM32F407（168 MHz Cortex-M4）上：
- sin(x)：321 FLOPs / 168M FLOPS ≈ 2 μs
- 抛体：8,448 FLOPs / 168M FLOPs ≈ 50 μs

**这个估算是理想情况**，实际要考虑：函数调用开销、内存访问延迟、Cache 命中率。

### E-22 浮点 vs 定点

| 格式 | 字节数 | 精度 | 计算速度 | 适用场景 |
|------|--------|------|---------|---------|
| float64 | 8 | ~15 位十进制 | 最快 | 通用计算，精度要求高 |
| float32 | 4 | ~7 位十进制 | 快 2× | 大多数嵌入式场景 |
| int16 | 2 | ~5 位十进制 | 快 4× | 对精度要求不高的场景 |
| int8 | 1 | ~3 位十进制 | 快 8× | 边缘设备、IoT |

**为什么不用更低精度？**

- int8 能表示 -128 到 127，但神经网络权重通常在 [-1, 1] 范围内 → int8 够用
- int16 能表示 -32768 到 32767 → 足够覆盖大多数权重范围
- 对于内存 1KB 以下的 MCU，int16 是很好的选择

**量化方法**：

```
原始值: float weight
量化值: int16 quantized = (int16)(weight × 32767 / max_range)
反量化: float recovered = quantized × max_range / 32767.0
```

### E-23 查找表加速激活函数

**核心思想：用查表替代计算。**

```c
// 预先计算 1000 个点的 Sigmoid 值，存入数组
float sigmoid_lut[1000];
for (int i = 0; i < 1000; i++) {
    sigmoid_lut[i] = 1.0f / (1.0f + expf(-5.0 + i * 10.0 / 999));
}

// 运行时：输入 x → 查表 → 近似结果
float sigmoid_fast(float x) {
    if (x <= -5.0f) return 0.0f;
    if (x >= 5.0f) return 1.0f;
    int index = (int)((x + 5.0f) / 10.0f * 999.0f);
    return sigmoid_lut[index];
}
```

**查表 vs 计算**：

| 方法 | 时间 | 精度 |
|------|------|------|
| expf() 计算 | ~100 ns | 精确 |
| 查找表（1000 点） | ~5 ns | 精确到 0.005 |
| 查找表（100 点） | ~2 ns | 精确到 0.05 |

对于 STM32F407（168 MHz），查表能将激活函数的计算速度提高 20 倍。

> **检查点**：为什么查表只需要 1000 个点就能覆盖 [-5, 5] 的范围？

### E-24 内存池管理

**问题**：nn.c 中每层调用 `malloc` 分配 `weights`、`biases`、`net`、`out`、`error` 数组。在嵌入式平台上，频繁 malloc/free 会产生内存碎片。

**解决方案：预先分配一块大内存，手动管理分配。**

```c
// 伪代码
float pool[MAX_POOL_SIZE];
int pool_used = 0;

float* pool_alloc(int size) {
    float* ptr = &pool[pool_used];
    pool_used += size;
    return ptr;
}

void pool_free_all() {
    pool_used = 0;
}
```

**当前项目适用性**：`nn.c` 的 `nn_add_layer` 在创建时分配一次，`nn_destroy` 在销毁时释放一次——不存在频繁 malloc/free 的问题。但如果要在 MCU 上运行，建议在初始化时一次性分配所有缓冲区。

### E-25 SIMD 指令加速

**核心思想：一次计算多个值。**

普通循环：

```c
for (int i = 0; i < 100; i++) {
    out[i] = weights[i] * input[i] + biases[i];  // 100 次乘法和加法
}
```

SIMD 加速：

```c
// ARM CMSIS-DSP 或 NEON 指令，一次处理 4 个 float
for (int i = 0; i < 100; i += 4) {
    float32x4_t in_vec = vld1q_f32(&input[i]);
    float32x4_t w_vec  = vld1q_f32(&weights[i]);
    float32x4_t b_vec  = vld1q_f32(&biases[i]);
    float32x4_t out_vec = vfmaq_f32(w_vec, in_vec) + b_vec;
    vst1q_f32(&out[i], out_vec);
}
```

**加速效果**：理论上 4 倍加速（实际受内存带宽限制，通常 2~3 倍）。

## 第六章 端到端项目实战

### E-26 需求分析

**什么问题适合用神经网络？**

| 适合 ✅ | 不适合 ❌ |
|--------|----------|
| 输入输出关系复杂（无法用公式表达） | 规则明确的逻辑判断（if-else） |
| 有大量数据可以训练或仿真 | 样本极少且无法生成 |
| 允许近似解（不要求 100% 精确） | 需要 100% 正确的安全关键逻辑 |
| 环境有噪声、不确定性 | 需要形式化验证 |

**你的三个任务的适用性分析**：

| 任务 | 适合 NN？ | 原因 |
|------|---------|------|
| sin(x) 拟合 | ✅ | 公式简单但可以学习近似解，数据无限 |
| XOR 逻辑 | ✅ | MLP 能完美解决，但规则明确也可以用 if-else |
| 抛体落点预测 | ✅ | 物理规律复杂，适合 NN 近似 |

### E-27 数据准备流程

```
原始传感器数据
    ↓ 去噪、滤波
    ↓ 特征提取（选哪些输入）
    ↓ 归一化/标准化
    ↓ 划分训练集/验证集/测试集
    ↓
可训练数据集
```

**关键决策**：

1. **特征选择**：选哪些传感器数据作为输入？不是越多越好，无关特征会干扰训练
2. **标注方式**：输出值怎么确定？是否需要人工标注？
3. **采样频率**：数据的时间分辨率对结果影响很大

### E-28 模型开发迭代

```
迭代循环：

1. 设计网络结构（层数、宽度、激活函数）
2. 用少量数据快速训练，观察趋势
3. 如果 Loss 不降 → 检查数据质量/网络结构
4. 如果 Loss 降但验证效果差 → 减小模型或增加正则化
5. 重复 2~4 直到满意
6. 用大量数据最终训练
```

### E-29 模型压缩

| 技术 | 原理 | 效果 | 适用场景 |
|------|------|------|---------|
| 权重剪枝 | 去掉接近 0 的权重 | 减少 30~90% 参数 | 权重大、稀疏模型 |
| 量化（float32→int16） | 降低精度换速度 | 减少 50% 内存 | MCU 部署 |
| 知识蒸馏 | 用大模型教小模型 | 保持 90%+ 精度 | 大模型 → 嵌入式 |
| 结构压缩 | 用更高效的层设计 | 减少计算量 | 深度版模型 |

### E-30 部署验证

**验证清单**：

1. **精度验证**：用测试集对比预测值和真实值的平均误差
2. **性能验证**：测量一次推理的时间是否满足实时性要求
3. **边界测试**：输入极端值（0、很大、负数）时是否崩溃或输出异常
4. **回归测试**：修改固件后重新验证模型精度是否下降
5. **持久化验证**：保存/加载后精度是否一致

## 第七章 特征工程实战——时序信号的分类

前面 E-26~E-30 的端到端项目实战中，我们讨论了通用流程。本章用两个高级案例，聚焦一个关键步骤：**特征工程**——如何把原始传感器数据变成神经网络能处理的定长向量。

这两个案例都涉及时序信号（加速度、音频），而 MLP 只能处理定长输入。从变长时序到定长向量的转换，就是特征工程的核心任务。

### E-31 手势/动作识别

**问题**：根据加速度计（如 MPU6050）的时序数据，识别用户的手势——静止、挥手、敲击、摇晃。

**核心挑战**：加速度计每秒产生 100 个采样点（X/Y/Z 三轴），一次手势持续约 0.5 秒，就是 150 个数据点。但 MLP 需要固定长度的输入，且不同手势的持续时间不同。

**解决方案**：提取统计特征，把变长时序变成 12 维定长向量。

```c
// file: docs/example/task_gesture.c

// 对每个轴提取 3 个统计特征：
static void extract_features(const double *ax, const double *ay, const double *az,
                              int n, double *features)
{
    for (int axis = 0; axis < 3; axis++) {
        // 均值：整体偏移（静止时接近重力方向）
        // 方差：波动程度（挥手/摇晃时大，静止时小）
        // 峰值：最大绝对值（敲击时有尖锐峰值）
    }
    // 合成特征：
    // 总能量 = Σ(ax² + ay² + az²) / n
    // 过零率 = 信号穿过零点的频率（挥手时高，静止时低）
    // 峰峰差 = max(magnitude) - min(magnitude)（摇晃时大）
}
```

**12 个特征的物理含义**：

| 特征 | 静止 | 挥手 | 敲击 | 摇晃 |
|------|------|------|------|------|
| X 均值 | ≈0 | 大 | ≈0 | 大 |
| Y 方差 | 小 | 大 | 中 | 大 |
| Z 峰值 | 小 | 中 | **极大** | 大 |
| 总能量 | 小 | 中 | 中 | **极大** |
| 过零率 | 低 | **高** | 中 | 高 |
| 峰峰差 | 小 | 大 | 中 | **极大** |

**数据模拟方式**（`task_gesture.c`）：

```c
// 每种手势用不同的数学函数模拟：
case 1: /* 挥手 */ ax[i] = amp * sin(2π × 3Hz × t);  // X 轴 3Hz 正弦
case 2: /* 敲击 */ az[i] = amp * 1.5 * sin(2π × 8Hz × t) * exp(-3t); // 衰减脉冲
case 3: /* 摇晃 */ ax[i] = amp * sin(5Hz) + 0.5*amp * sin(7.3Hz);    // 多频叠加
```

**网络结构**：

```
输入(12: 统计特征) → 隐藏(32, ReLU) → 隐藏(32, ReLU) → 输出(4, Softmax)
```

**运行方式**：

```cmd
train_demo.exe
# 选择 8. 手势动作识别
```

**观察重点**：

1. 训练后准确率能达到多少？（目标 > 90%）
2. 如果减少特征数量（比如只用 X/Y/Z 均值 3 个特征），准确率会怎样？
3. 思考：这个方案在真实 MCU（如 STM32F4, 168MHz）上的推理时间是多少？

### E-32 语音命令识别

**问题**：根据音频信号的声学特征，识别 5 个语音命令——"开灯"、"关灯"、"增大"、"减小"和噪声。

**核心挑战**：音频信号比加速度更复杂。采样率 16kHz 时，0.5 秒就是 8000 个数据点。直接喂给 MLP 完全不可行。

**特征工程方案**：MFCC（Mel 频率倒谱系数）。这是语音识别领域最经典的特征提取方法。本案例用简化的频谱包络模型模拟 MFCC 特征。

**为什么需要 MFCC？**

```
原始音频波形 (8000 维) → 太高维，MLP 无法处理
       ↓ STFT（短时傅里叶变换）
频谱图 (频率 × 时间)   → 变长，且包含冗余信息
       ↓ 取频谱包络 + DCT
MFCC 特征 (13 维)       → 定长、低维、保留语音辨识信息
```

**代码中的模拟方式**（`task_voice.c`）：

```c
// 用高斯峰模型模拟不同语音的频谱包络
// 每个语音命令有不同的共振峰分布（formant）
case 0: /* "开灯" /ai/ */  F1≈频带2-3, F2≈频带6-7 → 低频突出
case 1: /* "关灯" /uan/ */ F1≈频带3-4, F2≈频带7-8 → 中频突出
case 2: /* "增大" /zeng/ */ 辅音高频偏移 + F2 偏高 → 高频突出
case 3: /* "减小" /jian/ */ 三共振峰 → 中高频分布
case 4: /* 噪声 */        频谱平坦
```

**网络结构**：

```
输入(13: MFCC特征) → 隐藏(64, ReLU) → 隐藏(32, ReLU) → 输出(5, Softmax)
```

**运行方式**：

```cmd
train_demo.exe
# 选择 9. 语音命令识别
```

**观察重点**：

1. 训练后准确率多少？（目标 > 85%，因为模拟数据是简化的）
2. 对比动作识别案例——哪个更容易训练？为什么？
3. 注意看"噪声"类别的识别率——通常比其他类别低，因为噪声的模式不固定

**从 MLP 到真实语音识别的差距**：

本案例的 MFCC 特征是模拟生成的，与真实语音差距较大。实际产品中的语音识别需要：

| 本案例 | 真实产品 |
|--------|---------|
| 13 维模拟特征 | 13~26 维真实 MFCC |
| 4 个类别 | 10~30 个命令词 |
| MLP 网络 | CNN/RNN/Transformer |
| 95% 准确率（模拟数据） | 95%+ 准确率（真实数据，需大量训练） |

这正好是深度进阶版（`04-深度进阶版-前沿架构与拓展.md`）要讲的内容。
